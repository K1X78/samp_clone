## Prior source owners and reachability

The other seven addresses have same-start comments in `src/client/core/pickup_pool.cpp` at lines 7, 24, 34, 47, 55, 62, and 73. I read that complete file and confirmed its host abstraction stores the game index through a reference, plus matching destroy/count/cooldown/index/notification/process effects. The core and net implementations are separate targets; the net pool is in the `samp_client` source set used by `samp_client_dll`, while `samp_client_core` is not linked into that DLL. These are prior count claims/owner collisions, not simultaneous runtime objects. No repeated candidate address among the nine methods within the imported file.

`CreateWeapon` currently has no located caller and no proven exact owner. `SendNotification` is reachable from the installed game hook; normal pickup creation/destruction and weapon-owner destruction are registered RPC paths; Process is called by the netgame loop. The class/record extent typedefs are compile-time layout checks, not extra function bodies.
