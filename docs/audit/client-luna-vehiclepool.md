## Existing same-start claims and reachability

- `src/client/win/vehicle_runtime.cpp:12` claims `FUN_1001eb40`; that script-based runtime spawn function has additional bounds/finite checks and does not perform the net CVehiclePool record/active-table work, so it is not an equivalent pool body.
- `src/client/win/vehicle_runtime.cpp:91` claims `FUN_1001e540`; it removes occupants and deletes by GTA script handle through a separate runtime map, not the official pool active/plate/object/backend cleanup sequence.
- `src/client/core/vehicle_sync.cpp:73` claims `FUN_1001ecf0`; it matches the send/reset behavior except for an extra `state_==Connected` gate, which official code does not test. Remove that extra condition if retaining an equivalent owner claim.

Those are separate `samp_client_win`/`samp_client_core` targets, not normal deployed `samp_client_dll` bodies. They remain source/count claim collisions; current net source contains the closer normal-runtime owners. No repeated address within `vehiclepool.cpp`.

Unindexed hints `0x10002df0`, `0x1001e730`, `0x1001e7d0`, `0x1001e6a0` have no exact owner C/body/assembly; three also have no source caller. `SetUnoccupiedSyncOwner` and `ProcessWaitingList` have no source caller; `FindNearestToPoint`, `Queue`, `GetRef(void*)`, `FindInLine` likewise have no direct source callers located. This is a reachability note, not an exclusion or guessed mapping.
