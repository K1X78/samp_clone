## Findings

- **UNRESOLVED — `CActorPool::Get(WORD id)`, source line 7; comment hint `0x00001610` → candidate `0x10001610`.** `index.tsv` has no exact entry. The next exact indexed start is 0x10001640; no exact owner C/body range or assembly evidence supports the hint. Source returns actor pointer only when id<1000 and active, otherwise null. Do not add an Official pointer from the hint.
- **MATCH — `CActorPool::DoesExist(WORD id)`, line 12; `FUN_10001640 @ 0x10001640`, body `0x10001640..0x1000165c`.** `__thiscall`; ECX=this, WORD id on stack, callee pops 4; returns raw active DWORD in EAX, or zero for id>=1000. Direct assembly confirms unsigned bound and direct DWORD load. Official static-reference table has no known direct callers (indirect/API calls may be absent); source paths use the raw flag. Prior claim: `ActorSlots::used_flag` (`src/client/core/actor_slots.cpp:65`), which returns the corresponding stored flag.
- **MATCH — `CActorPool::UpdateLargestId()`, line 19; `FUN_10001660 @ 0x10001660`, body `0x10001660..0x100016b4`.** Argumentless member call: this in ECX, no explicit stack arguments. Walks the active bank in five-entry batches and writes the greatest active index, defaulting to 0. Direct assembly confirms complete 1000-entry scan and update ordering; source's ascending scan leaves the same last active value. Official callers include Delete (0x1000173b) and Create (0x10001a06); clone callers are Create/Delete in this pool. Prior claim: `ActorSlots::recompute_occupied` (`core/actor_slots.cpp:17`), behavior equivalent for the bounded used bank.
- **MATCH — `CActorPool::CActorPool()`, line 28; `FUN_100016c0 @ 0x100016c0`, body `0x100016c0..0x100016e8`.** Argumentless constructor: this in ECX, no explicit stack arguments. Zeroes count and 1000 actor pointers, active DWORDs, and ped pointers; leaves two other per-slot DWORD banks untouched. Assembly confirms offsets/iteration. Lifecycle callers include 0x10008230 and 0x10009180; clone pool construction/reset at `netgame.cpp:1145,1228–1234`. The alternate core `ActorSlots::clear` claim (`core/actor_slots.cpp:11`) also resets unique_ptr actor objects and its network-id bank, effects absent from this native constructor; the old claim is not equivalent for a populated table.
- **MATCH — `CActorPool::Delete(WORD id)`, line 39; `FUN_100016f0 @ 0x100016f0`, body `0x100016f0..0x10001750`.** `__thiscall`, WORD id, BOOL EAX, callee pops 4. Requires id<1000, active flag, and nonnull actor. Clears active, calls virtual deleting destructor slot 0 with flag 1, clears actor and ped pointers, recomputes largest id, returns TRUE; failure returns FALSE with no changes. Source `delete actor` matches the virtual deleting-destructor effect and state updates. Official direct callers include destructor 0x100018e9 and Create replacement 0x10001944. Clone RPC destroy handler calls Delete (`scriptrpc.cpp:773–781`, RPC registration 172 at 1170 and 1290). **Prior claim:** `ActorSlots::remove` (`core/actor_slots.cpp:30`) does not require the active flag and clears a network-id bank, rather than this native ped-pointer bank; its behavior diverges on inconsistent slot state and its Find mapping below is not equivalent.
- **MATCH — `CActorPool::~CActorPool()`, line 52; `FUN_100018e0 @ 0x100018e0`, body `0x100018e0..0x100018f8`.** Argumentless member destructor: this in ECX, no explicit stack args. Calls Delete for every WORD id 0..999; void return. Assembly confirms loop and WORD bound. Lifecycle callers include 0x10009570, 0x10009180, 0x100084b0; clone netgame teardown/reset. Prior claim: `ActorSlots::delete_all` (`core/actor_slots.cpp:58`), but delegates to its non-equivalent `remove` behavior described above.
- **MATCH — `CActorPool::Find(void* ped)`, line 58; `FUN_100018b0 @ 0x100018b0`, body `0x100018b0..0x100018d6`.** `__thiscall`, pointer argument on stack, returns slot in AX and callee pops 4. If largestId>=0, scans ped-pointer bank from zero through largest inclusive; returns first equal slot. On miss, exact assembly uses `OR AX,0xffff`, preserving the high half of the terminating counter; source's WORD return matches the meaningful 16-bit result, and current callers use a WORD. Official incoming refs 0x100060d0 and 0x100a38e0; clone callers include `GameHook` at `hooks.cpp:2478–2479` and localplayer actor selection at `localplayer.cpp:1579`. **Prior claim:** `ActorSlots::find_by_network_id` (`core/actor_slots.cpp:47`) searches a network-id vector, whereas official compares the ped-pointer bank. That prior body is not an equivalent implementation of this owner.
- **MATCH — `CActorPool::Create(const ActorCreateInfo*)`, line 76; `FUN_10001900 @ 0x10001900`, body `0x10001900..0x10001a77`.** `__thiscall`, pointer to packed 31-byte `ActorCreateInfo` on stack, BOOL EAX, callee pops 4. No ID bounds check. If an actor pointer already exists, logs the warning then attempts Delete. Allocates a 0x56 CActor; constructor args use packed offsets model +2, position +0x0a/+0x0e/+0x12 and heading +0x16. On success stores backend pointer from actor+0x48, sets active, applies health/invulnerability, writes state banks, recomputes largest id, then applies custom model when global manager exists and custom model>20000 and either GameIsPedModel or custom DoesExist succeeds. On allocation failure it returns FALSE in the explicit branch; the official operator_new uses the normal throwing new-handler contract previously verified, so this null branch is not by itself a mismatch with C++ `new`. Direct assembly confirms no id check, replacement path, offsets, call args and status stores. Official caller 0x1000e940; clone `ScrCreateActor` at `netrpc.cpp:704–718`, registered RPC 171 (`netrpc.cpp:1168–1170,1289–1290`). **Prior claim:** `GameRuntime::create_actor` (`src/client/win/actor_runtime.cpp:8`) creates a ped through script commands in a separate runtime API, imposes different bounds/model preconditions and does not implement this CActorPool state/ABI body; do not treat its pointer claim as proof of an equivalent body.
- **MATCH — `CActorPool::FindInRay(float,const CVector*,const CVector*,float)`, line 111; `FUN_10001770 @ 0x10001770`, body `0x10001770..0x100018ad`.** `__thiscall`; ECX=this; stack max-camera-distance float, origin pointer, end pointer, rayValue float; callee pops 0x10. Returns selected slot/0xffff in AX. Scans 0..largestId, filters active/id<1000/non-null actor, DoesExist, camera distance `< max`; initializes two 20-byte ray records with the 12-byte vectors plus the input float and leaves their trailing DWORDs uninitialized; calls line-sphere test with entity backend, centre, radius 1.5 and camera-check 1; chooses the hit with nearest distance from origin below 100000. Source structure/effects match the direct C+asm flow. `GameTestEntityLineSphere` contract was checked at official `0x100b6110` and source `game.cpp:1673–1680`; source passes corresponding origin/end/backend/centre/scale/camera args. Official incoming reference 0x10004300; real clone caller is actor-target selection in `localplayer.cpp:1880` (FindInRay also used for objects, vehicles, players with their respective pools). No existing same-start claim; this is the one newly unique exact start in this file.
