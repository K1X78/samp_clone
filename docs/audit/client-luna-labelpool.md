## Function findings

All exact candidate functions have `assembly_entry: true`, status `ok`, and body ranges equal to the reported owner body. Complete C bodies through their END markers and direct assembly for each owner were read. Caller metadata and concrete clone paths are included per item.

- **UNRESOLVED — `CLabelPool::IsActive(WORD id)`, source line 18; hint `0x0000e3c0` → candidate `0x1000e3c0`.** `index.tsv` has no exact entry. No owner C/assembly or reliable caller-to-owner proof exists for this hint. Source returns `active[id]` for `id < 2048`, else 0. Keep it unresolved; do not add this address as a mapping.
- **MATCH — `CLabelPool::CLabelPool()`, source line 23; owner `FUN_10001190 @ 0x10001190`; body `0x10001190..0x100011cb`.** Argumentless member constructor: `this` in ECX, no explicit stack arguments. Zeroes each of 2048 contiguous 29-byte `TextLabel` records and the separate 2048-DWORD active bank at `this+0xe800`; direct assembly confirms 0x800 iterations and byte/DWORD widths. No failure path. Official static callers include 0x10008230 and 0x100090e0; clone pool construction/reset: `netgame.cpp:1139,1220–1225`. **Prior claim:** `WorldTextTable::clear` in `src/client/core/world_text.cpp:11` claims this same VA. Its implementation also resets/frees each `names_` allocation, an effect absent from this official constructor, so the prior body is not equivalent. Same-start claim is a source/count collision, not a second runtime implementation of this net pool.
- **MATCH — `CLabelPool::~CLabelPool()`, source line 32; owner `FUN_100015e0 @ 0x100015e0`; body `0x100015e0..0x1000160b`.** Argumentless member destructor: `this` in ECX, no explicit stack arguments. Scans 2048 active DWORDs and invokes owner `0x100012e0` only for active entries; void return. Assembly confirms the active-bank walk, WORD-sized loop bound test, and call. Official lifecycle callers 0x10009570, 0x100090e0, 0x10008510. Clone lifecycle: `CNetGame::ResetLabelPool` at `netgame.cpp:1218–1225`; teardown path at `netgame.cpp:1021–1025`. **Prior claim:** `WorldTextTable::remove_all` in `core/world_text.cpp:75` claims this VA; it similarly walks used entries and delegates removal, but its delegated storage/allocation contract differs (see Create/Remove notes in the existing core source). Treat it as an alternate-target same-start claim, not proof by itself.
- **MATCH — `CLabelPool::Create(WORD,const char*,DWORD,CVector,float,BYTE,WORD,WORD)`, source line 39; owner `FUN_100011d0 @ 0x100011d0`; body `0x100011d0..0x100012dd`.** `__thiscall` owner: ECX=this; stack has WORD id, text pointer, DWORD color, 12-byte by-value `CVector` (three 32-bit floats), float distance, BYTE flag, and two WORD IDs; callee pops 0x28 bytes. For id >= 2048, return without changes. When active, free old text if nonnull and zero the 29-byte record; then allocate `calloc(1,strlen(text)+1)`, copy including NUL, call `FUN_100b5c40(text,399)` only when text length <400, rotate RGBA to native ordering, copy vector/distance/flag/IDs, set active. The official code does not recover from allocation failure: it stores the result and writes through it; clone likewise has no OOM recovery. Assembly confirms unsigned WORD range check, allocation and copy, field offsets, and `ret 0x28`. Direct incoming caller 0x1000f5e0; clone dispatch is `ScrCreate3DTextLabel` in `netrpc.cpp:839–851`, registered with RPC 36 at `netrpc.cpp:1118–1120,1246–1247`. **Prior claim:** `WorldTextTable::create` in `core/world_text.cpp:22` claims the same VA but is behaviorally different: rejects null text, uses `make_unique` with a different allocation size/family, and omits the official `ChatPrepareMessage` call. Do not treat that prior claim as an equivalent body.
- **MATCH — `CLabelPool::Delete(WORD id)`, source line 70; owner `FUN_100012e0 @ 0x100012e0`; body `0x100012e0..0x1000134c`.** `__thiscall`, WORD id; returns BOOL in EAX and callee pops 4 bytes. Invalid id or inactive slot returns FALSE without effects. Active slot frees nonnull text, zeroes exactly the 29-byte record, clears active, returns TRUE. Assembly agrees on unsigned 0x800 bound, free/null branches, stores, return values. Official caller 0x1000f790; clone RPC `ScrDestroy3DTextLabel` at `netrpc.cpp:854–865`, registered RPC 58 at `netrpc.cpp:1118–1120,1246–1247`. The destructor calls this owner. **Prior claim:** `WorldTextTable::remove` in `core/world_text.cpp:61` claims this VA; control flow/state clearing is similar, but it releases its `unique_ptr<char[]>` allocation rather than the official `_free` of a `calloc` buffer produced by the paired official Create.
- **MATCH — `CLabelPool::Draw()`, source line 81; owner `FUN_10001350 @ 0x10001350`; body `0x10001350..0x100015d3`.** Argumentless member call: `this` in ECX, no explicit stack arguments. Prefer the assembly targets over the pseudocode callee labels for these calls. Official static incoming reference: 0x100751b0. Real clone caller: D3D render hook `IDirect3DDevice9Hook.cpp:839`; creation/destruction occurs through the RPC paths above. **Prior claim:** `WorldTextTable::render` in `core/world_text.cpp:85` claims this VA, but is a separate host abstraction returning a draw count; it does not establish matching clone ABI/call sequence by the pointer.
